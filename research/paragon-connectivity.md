# Paragon node connectivity and allocation research

## Scope and evidence

This investigation is limited to the Paladin starting board and its 17 referenced node definitions at DiabloTools/d4data commit [`75e619f0d90a0951945747f45feef59c076a5db0`](https://github.com/DiabloTools/d4data/tree/75e619f0d90a0951945747f45feef59c076a5db0). The board source is [`json/base/meta/ParagonBoard/Paragon_Paladin_00.pbd.json`](https://github.com/DiabloTools/d4data/blob/75e619f0d90a0951945747f45feef59c076a5db0/json/base/meta/ParagonBoard/Paragon_Paladin_00.pbd.json); the local copy matches it, as documented in [`paladin-source-verification.md`](./paladin-source-verification.md).

The connectivity rules below were supplied after in-game testing by the project owner. Blizzard's published design articles remain useful background, but the detailed Paragon description is from 2021 and does not establish that every rule remained unchanged in the 2026 data revision.

## VERIFIED — Extracted board and node data

- The board is a `ParagonBoardDefinition` with `nWidth: 21` and 441 row-major `arEntries` slots. There are 75 occupied slots referencing 17 unique `ParagonNode` definitions.
- Occupied entries are node SNO references (`__raw__`, `__targetFileName__`, `groupName`, and `name`). The board has no explicit edge, neighbor, path, or connection list. The 17 referenced node definitions likewise provide no such connection fields. This is a finding about the inspected board and node assets, not an exhaustive claim about every file in the repository.
- Counting occupied positions one grid step apart yields 110 orthogonal pairs and 100 diagonal pairs. These are geometric candidates only; `arEntries` does not identify any of them as valid game edges. Empty cells also make it unsafe to equate a grid step with a game connection.
- Relevant node definitions are [`StartNodePaladin.pgn.json`](https://github.com/DiabloTools/d4data/blob/75e619f0d90a0951945747f45feef59c076a5db0/json/base/meta/ParagonNode/StartNodePaladin.pgn.json) (SNO 2436489), [`Generic_Gate.pgn.json`](https://github.com/DiabloTools/d4data/blob/75e619f0d90a0951945747f45feef59c076a5db0/json/base/meta/ParagonNode/Generic_Gate.pgn.json) (SNO 994337), and [`Generic_Socket.pgn.json`](https://github.com/DiabloTools/d4data/blob/75e619f0d90a0951945747f45feef59c076a5db0/json/base/meta/ParagonNode/Generic_Socket.pgn.json) (SNO 681756). The gate has `bIsGate: true`; the socket has `bHasSocket: true`; the start definition has empty `ptAttributes` and no corresponding start/connectivity/allocation flag. These fields classify node properties; they do not encode edges or point costs.

## VERIFIED — In-game rules supplied for Phase 5

- Connections are orthogonal only; diagonal neighbors do not connect.
- A node may be allocated when it is orthogonally adjacent to an allocated node. Allocations can branch.
- A refund is prohibited if it would leave any remaining allocated node disconnected from the starting node.

## VERIFIED — Published gameplay descriptions

- Blizzard's [December 2021 Quarterly Update](https://news.blizzard.com/en-us/diablo4/23746639/diablo-iv-quarterly-update-december-2021) describes beginning on the class board's starting tile, progressing outward, and using Paragon points to unlock a connected tile. It describes gate tiles as enabling selection and attachment of another board, and sockets as tiles that can hold glyphs.
- Blizzard's [May 2023 customization overview](https://news.blizzard.com/en-us/diablo4/23938756/make-sanctuary-yours-play-your-way-in-diablo-iv) says Paragon points can unlock nodes and additional boards. These articles establish the broad design concepts, but neither specifies orthogonal versus diagonal edges, the exact cost of special tiles, or refund invariants.
- A [June 2023 player report on Blizzard's forum](https://us.forums.blizzard.com/en/d4/t/unable-to-refund-paragon-points-due-to-is-saying-it-cannot-break-connection-to-another-node/52002) quotes an in-game message about not breaking a connection when refunding. This is anecdotal user-generated evidence, not an official rule statement; the thread also discusses possible socket-removal confusion.

## Prototype assumptions — Not verified by node data

- The viewer starts with the starting node allocated at zero cost. The source definition does not specify whether this node consumes a point.
- Every other node costs one point in the prototype, including gates and sockets. The definitions do not specify these point costs.
- Costs are centralized in `POINT_COSTS` in `paragon-visual/app.js` so the assumptions can be changed without changing node data.

## UNRESOLVED — Questions for an accurate calculator

1. Is an explicit edge graph stored in another data asset or generated by the game? No separate connection asset is referenced by the inspected board or node definitions.
2. Are there special point costs or allocation/refund rules for gates and sockets beyond the prototype assumptions?
3. Do the historical descriptions above still match every runtime rule for the pinned 2026 data revision?

## Implementation recommendation

The viewer now constructs an orthogonal adjacency graph directly from occupied `arEntries` positions and uses breadth-first traversal to preserve connectivity on refunds. These graph rules reflect the project owner's in-game tests; point costs remain provisional. The extracted board and node data alone still cannot establish point costs or prove that no other relevant mechanics exist.
