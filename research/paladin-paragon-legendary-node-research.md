# Chapter III — Stage 1A: Paladin Legendary Paragon node research

All nine Legendary board nodes resolve to a pinned passive power and an English tooltip. Castle and Shield Bearer scale from character-wide defensive values. Preacher combines Zealot-specific Attack Speed with a separate conversion from Bonus Attack Speed to damage. Fervent, Divinity, Relentless, Sentencing, Endure and Beacon depend on combat state or events. Divinity's damage and Relentless's Cooldown Reduction still depend on an unbound Legendary-node intrinsic. Four class powers explicitly read the purchase flag and formula values of a Legendary node.

## Per-node mechanics and numerical predictions

Unless noted, the board-power tooltip specifies no damage element, skill family, separate resource cost or cooldown. Generic wording leaves the applicability to skills, damage over time, Thorns, companions and other indirect damage unresolved. Numeric examples are **DERIVED FROM DATA**. They show isolated modifier magnitudes, with no combined damage prediction.

### 01 · Castle — Armor DR conversion

- **VERIFIED — DATA.** The power evaluates `min(1.50, 1.25 × ComputeArmorDamageReduction())`. The display describes a conversion from the damage reduction granted by Armor and shows its result to one decimal with multiplicative notation. The formula reads the intrinsic result as a fraction.
- **DERIVED FROM DATA.** At 0%, 40%, 80% and 90% Armor DR, the Current Bonus predicts **0.0%, 50.0%, 100.0% and 112.5%[x]**. The script's 150% output clamp would first bind at a 120% intrinsic result. The pinned global `flMaxArmorReduction = 0.8999999761581421` makes 112.5% a plausible upper display if the intrinsic uses that capped Armor DR. The exact binding, difficulty or target context, and character-sheet equivalence still need validation.
- **Dependency.** `Armor_Total` reads effective Armor, bonus Armor and Strength-derived Armor, then applies `Armor_Percent`. The planner already models ordinary Armor Percent and can amplify eligible node lines, but has no full equipment Armor or Armor-to-DR evaluator. Defiance-like Armor threshold bonuses, glyph amplification and Defiance Aura can change the upstream input. A measured Armor DR percentage is a suitable research input before attempting to reconstruct the conversion from raw Armor. ### 02 · Shield Bearer — Phalanx, Block Chance conversion

- **VERIFIED — DATA.** `Block_Chance` (331, unparameterized, operator 0) is read directly. The script caps the input at `1` and multiplies it by `1.1`. The tooltip specifies a character stat and contains no block-event trigger. The separate `Block_Damage_Percent_Total` formula and its reduction cap describe a different input.
- **DERIVED FROM DATA.** At 0%, 25%, 50%, 75% and 100% Block Chance, Current Bonus predicts **0.0%, 27.5%, 55.0%, 82.5% and 110.0%[x]**. An illustrative raw input of 120% still returns 110.0%. Near a 50% baseline, an ordinary +2-point Block Chance source would increase the predicted bonus by 2.2 points if it is included in `Block_Chance` and the cap is inactive.
- **Interaction and limits.** Shield, skill and other global contributions may feed the input. Resolve native and amplified Block Chance and eligible ordinary Rare bonuses before any derived prediction. The named Phalanx skill has its own soldier, attack and passive sources. It appears neither in this node's formula nor in its linked-power arrays. No evidence assigns this damage bonus exclusively to soldiers or to hits following a successful block. ### 03 · Fervent — two modifiers per Fervor stack

- **VERIFIED — DATA.** `Paladin_Oath_Zealot` (2273665) SF15 reads node 2438099 via `ParagonNodeIsPurchased`. SF16 and SF17 read this passive's SF0/SF1 via `PowerTag`. The Oath tooltip grants Fervor on Zealot skill casts. Oath SF0 is `3 + SF_18`, where SF18 is `Paladin_Fervor_Stack_Bonus` (818, operator 0, unparameterized). SF1 is `2 + SF_4 * SF_6`, with SF4 the equipped check and SF6 static value at index 1 of `legendary_paladin_036` (2445850), whose `arStaticValues` are `[1, 2]`. Its finite buff ID 1 uses SF1, with an authored max stack of 1 on that buff. Preserve the Oath's Fervor count and duration as separate inputs from the board node.
- **DERIVED FROM DATA.** At 0, 1, 2 and 3 active stacks, a linear reading of the tooltip gives **0/0, 35/3, 70/6, 105/9** percentage points of nominal Critical Strike Damage `[x]` / Critical Strike Chance `[+]`, respectively. The Oath expressions produce a nominal count parameter of 3 at stat 818 = 0 and 4 at stat 818 = 1. At 4 actual stacks the linear reading is 140/12. ## Proposed implementation architecture

1. Use a revision-pinned board/node/power registry and resolve source cell identity at allocation time. Create a list such as `legendaryNodeEffects` with an owning board instance, node source index, node SNO and power SNO per effect. Add a component identity for Fervent, Preacher and Relentless. Preserve source links, preview versus granted state, effect units, predicates, formula input status and evidence. Connected results can concatenate owned records using instance and source cell identity. Refresh those records from existing allocations on restore.
2. Reuse the Stage 6B distinction between grant and combat eligibility. **Fixed scoped modifier:** Preacher's Zealot Attack Speed has a fixed magnitude and skill filter. **Conditional modifiers:** Divinity, Endure and Beacon read actor, target or Aura states, and Fervent reads the external Fervor count with separate Crit outputs. **Timed modifiers:** Relentless reads motion state and time since the last qualifying movement. **Target debuff:** Sentencing needs a Judging event and target lifetime with applying-player ownership. Leave dispatch and composition to a future combat evaluator. The nine nodes have no directly authored resource gain or seconds-off-active-cooldown event. Relentless is a percentage Cooldown Reduction modifier, and effects such as Aura Faith spend, Fervor Fortify and glyph Resplendence remain distinct.
3. Keep Castle, Shield Bearer and Preacher's damage conversion downstream of the full character input snapshot. The current planner has external core attributes and Paragon-only totals. Start with explicit measured scenario values for Armor DR, Block Chance or Bonus Attack Speed, with provenance and missing-input handling. A future character-stat evaluator can derive them after ordinary and Primary-amplified per-node contributions, native Rare thresholds and equipment/skill effects resolve. Castle may need an additional Armor-to-DR pass after Strength and Armor bonuses. Shield Bearer requires a capped Block Chance read. Preacher may need split general, tagged and per-power speed reads, with a fixed dependency order if its own Zealot component is verified as an input. If a scenario value already includes Paragon, use it as the resolved total and avoid adding the same bonuses a second time.
4. Preserve operation-1 base deltas on their node lines and operation-2 Primary contributions on their socket owners. Keep Board Legendary output out of glyph aggregates, `effectiveNodeContributions`, the shared core snapshot, Rare threshold inputs and additive `rawBonuses` until an exact mapping supports aggregation. State-dependent effects should remain inactive or indeterminate when the relevant state is absent or unknown. The four inbound class-power references describe consumers of the same passives. Treat their formula reads as provenance so a later class simulation cannot apply the same bonus again. Avoid back-feeding damage outputs into the source-stat snapshot.
