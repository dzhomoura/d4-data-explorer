# Stage 5A Paladin node amplification calibration

## Executive summary

All six Paladin amplification glyphs use the same authored **operation 1**, the same literal **0.001** budget, and four affix records differentiated by target rarity and scalar coefficients. Challenger’s observed coefficients support the rank-one curve `P(L) = 20 + 0.8085 × (L − 1)` in percentage points. The same calculation architecture can represent the other five glyphs using their authored coefficients, with source-derived status for their predictions. The operation-2 conversion glyphs use a different budget chain. The 0.033 intrinsic hypothesis from Stage 4 does not enter this operation-1 path.

Challenger’s observations establish that amplified Normal core points can appear in both global attributes and its local Additional requirement. They also rule out summing the integer values displayed on individual nodes. Summing full-precision deltas and truncating the resulting positive gain fits six of seven socket and requirement states and all captured global Strength deltas. Level 10 remains a discrepancy: the socket and requirement imply **+3 STR**, while the global display implies **+2 STR**. This report recommends full-precision calculation with separately labeled display policy.

The source provides a common way to select Magic and Rare nodes and leaves attribute filtering and runtime precision incompletely specified. Its localization includes a glyph-modified Rare conditional bonus template. That supports a conditional display path, while the game magnitude, eligibility and merge behavior remain open. A provisional implementation can handle resolved base bonuses across all six glyphs and preserve Rare conditional values until an isolated observation establishes their amplification. The named attributes in the ten-board catalogue carry no conditional core gains, so the current candidate pipeline is acyclic.

**Source scope.** Diablo IV 3.2.4.74043, DiabloTools/d4data revision `75e619f0d90a0951945747f45feef59c076a5db0`. The experimental record is the player-supplied Stage 5A brief. It includes inferred values marked below, and no original captures were supplied for independent inspection. ### Candidate curve and prediction catalogue

For raw authored start `a`, slope `b` and level `L`:

```text
scalar = a + b × (L − 1)
amplification fraction g = 0.001 × scalar
displayed coefficient before rounding P = 100 × g
native unit delta = native value × g
effective node value = native value + delta
```

The single range and authored slope do not supply a breakpoint or level-specific cap on the coefficient. Stage 4B’s player-confirmed radius expansions at levels 25 and 51 alter which purchased nodes enter the pool. A change in the aggregate across those levels can come from membership without a discontinuity in the coefficient. The one-decimal Challenger displays at 1, 10 and 25 give nearest-tenth intervals of `[19.95,20.05)`, `[27.25,27.35)` and `[39.35,39.45)`. Holding the intercept at 20, the independent samples allow approximately **0.80625–0.8104167** percentage points per level. The nominal slope 0.8085 lies within that range. A rank-zero model with the authored intercept predicts about 20.8% at level 1 and fails. The level-31 prediction 44.255% rounds to 44.3%, consistent with the inferred label. Rank anchoring and multiplicative transformation of a node value are strong candidates, with exact internal execution unresolved.

## Precision models and residuals

For each STR state, the unrounded prediction uses one full-precision delta per eligible node, `5 × g`, with the non-targeted +10 Rare STR retained in the local pool. Compare five candidate presentation paths:

- **Aggregate truncation** truncates the sum of eligible node deltas toward zero.
- **Aggregate nearest** rounds the same sum to the nearest integer.
- **Node truncation** truncates each delta before adding.
- **Node nearest** rounds each delta before adding. For these integer native values, it also represents summing individually rounded effective node values and subtracting the native sum.
- **Node tenth** rounds each delta to the nearest tenth before summing and then truncates the aggregate. It tests intermediate quantization at a precision suggested by the visible coefficient. The coefficient itself is a percentage, so its formatting is independent of any such stat quantization.

Each entry below is the predicted integer gain followed by the signed residual against the socket, calculated as prediction minus observation. The same residual applies to the local numerator, since all seven observed local numerators equal native local STR plus observed socket STR. The global column uses the paired sheet readings and marks the inferred comparison.

For a single eligible +5 core node, the modeled deltas at the four sampled coefficients are 1, 1.363825, 1.9702 and 2.21275. All five models display +1 at levels 1 and 10, agreeing with Dexterity, including the captured global pair at level 10. At level 25, aggregate truncation and per-node truncation predict +1 per isolated node. Both nearest models and node-tenth predict +2. The local +1 DEX and +1 INT are consistent with the truncation candidates under the one-node assumption per stat. The supplied record identifies the newly included INT node but gives no complete allocation roster for non-STR stats. All five predict +2 for a single node at 44.3%, consistent with both recorded DEX and INT socket and global increments. WIL staying 86 establishes zero visible change in that state. It cannot identify a Willpower-specific runtime rule. The individually displayed +7 STR at 44.3% is consistent with either truncating or rounding 7.21275 to nearest. The five-node result shows the aggregate uses greater precision than those displayed integers.

A fixed shifted-floor rule `floor(raw + t)` with `0 ≤ t < 1` needs `t ≥ 0.27235` at level 10 and `t < 0.0596` at level 25. Those intervals do not overlap, even allowing the full rounding interval of each displayed coefficient. Reconstructing from the displayed coefficients alone gives 2.73 and 3.94, with the same conflict. A sample binary32 pipeline that rounds the authored slope multiplication, addition, budget multiplication and effective +5 node calculation at each step changes the STR deltas by less than 0.000003 in these observations. It cannot explain the integer discrepancy. Other intermediate or surface-specific quantizers remain possible. The same STR attribute disagrees between surfaces at level 10, so a single rule keyed only by attribute is insufficient.

The pinned `Strength_Total` formula applies Strength-specific and all-stat percent bonuses to a sum that includes `Strength_Core`. It is a float stat. Even with unit scaling, subtracting two floors yields `floor(frac(nativeTotal) + rawDelta)`. A hidden fractional baseline could change the integer sheet delta by a point. The paired integer displays cannot distinguish internal truncation from rounding or truncation of final presentation. Allocation, character total, node popup and local requirement should therefore remain separately labeled outputs in any investigation. [Pinned attribute definitions](https://github.com/DiabloTools/d4data/blob/75e619f0d90a0951945747f45feef59c076a5db0/attributes.json)

**Provisional precision policy.** Keep raw typed values through node deltas, aggregation and requirement evaluation. A clearly labeled integer preview may truncate the positive aggregate as a presentation choice. Retain exact diagnostics and use no offset or level exception. For a positive integer threshold T and an unquantized local pool x, `floor(x) ≥ T` is equivalent to `x ≥ T`. A runtime quantization step before aggregation could still change marginal outcomes. The 44.3% five-node case is comfortably clear of 40 under all tested models. Socket, individual node, requirement and global display parity remain unverified.

## Deterministic calculation dependencies

The current single-board calculator builds registered and formula-resolved native values, evaluates Rare thresholds with total attributes, and dispatches operation 2 after assembling node evaluations. The connected-board wrapper already combines unconditional core from all boards before each board’s threshold pass. It guards against conditional core gains and currently supplies other boards’ core through the external-attribute argument. That argument expects safe nonnegative integers, so routing fractional amplification through it would both violate its contract and blur provenance. The future pipeline can retain the existing native resolution, threshold registry and socket geometry, and supply a dedicated effective threshold context. [Calculator](../paragon-visual/paragon-calculator.js) · [Connected boards](../paragon-visual/connected-boards.js) · [Bonus registry](../paragon-visual/paragon-bonus-registry.js) · [Current Primary evaluator](../paragon-visual/glyph-primary.js)

1. **Resolve purchased native lines.** Use board instance and source index, typed attribute ID and parameter, attribute slot, and base or conditional component as identity. Keep native amount, units, provenance and threshold reference. The registry and validated formulas determine which values are resolved.
2. **Apply base amplification.** For each configured amplification glyph on a purchased socket, use the resolved node kind and the owned board’s radius membership to select purchased target nodes. Derive a separate raw base delta per eligible resolved line. Preserve native records and unknown values.
3. **Build global threshold inputs.** Combine effective unconditional core lines across all boards with supplied external character attributes in an internal context. Keep externally supplied attributes separate from Paragon exports. A Build Lab caller that models gear and character percent terms can consume the canonical flat Paragon deltas before its character transform or provide the resolved threshold context at that boundary.
4. **Evaluate Rare requirements.** Resolve each requirement from the existing threshold registry with the owning board’s placement index and the same global input snapshot. Retain unresolved requirements and inputs explicitly.
5. **Activate conditional native lines.** Include resolved conditional amounts only on allocated nodes whose requirements resolve and pass. Conditional amounts remain independently inspectable when inactive.
6. **Apply conditional amplification if supported.** Apply any later evidence-backed delta only to active, eligible conditional components. The provisional model leaves this delta pending. No current conditional component feeds back into the global core inputs.
7. **Build local glyph pools.** Sum effective core lines on the same board, purchased and inside that socket’s radius. Include non-targeted core values at their native amount. A socket summary is a projection of node deltas, so the same deltas stay out of any second contribution record.
